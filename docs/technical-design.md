# 精灵远征存档与技术方案

版本：设计草案 v1.1。日期：2026 年 10 月 15 日。配套：[游戏设计](game-design.md)。实际三馆模块与验证边界见 [实现记录](implementation.md)。

使用 React Native 承载界面与游戏逻辑，Skia 绘制像素场景，本地事务存储完整进度。Android 与 iPhone 使用同一个存档格式，通过局域网发现和直接传输互通。此文保留长篇设计目标；已实现模块、构建、自检与待完成的真机验收见[实现记录](implementation.md)，实际记录优先于本文早期拟建目录与配对提案。

M1 已采用 TCP / Zeroconf 原生库和 QR 固定公钥的 NaCl box 配对，未自建 Swift / Kotlin 通信模块，未实现六位短码认证。64 KiB 块经过 JS API，有 8 MiB 上限；不能将下文“数据流留在原生”的目标当作当前实现。Android / iOS 原生 loopback 与 SQLite 自检已通过，真实 Wi-Fi 双机矩阵尚未完成。

ch3.1 已采用目录内 `index` 的 RN 模块结构。新增 `environment` 独立天气随机状态、`rewards` 逐只结算记录、`capture` 球等级与大师球来源账本、`fieldSkills` 剧情解锁和中心服务；这些记录通过原有快照校验、原子存档和传档协议。具体公式见 [系统设计](world-systems.md)。

## 1 技术选择

| 层           | 方案                                                     | 目的                                              |
| ------------ | -------------------------------------------------------- | ------------------------------------------------- |
| 应用         | React Native、TypeScript、Expo 自定义开发构建            | 共享界面与规则，同时可接入 Swift／Kotlin 模块     |
| 开发基线     | 以 Expo SDK 57 稳定系列为候选                            | 初始化时重新核对兼容矩阵，锁定精确依赖与 lockfile |
| 画面         | React Native Skia，精细像素 sprite atlas，分层地块与特效 | 控制地块绘制、像素采样、动作与镜头表现            |
| 游戏规则     | 独立纯 TypeScript 模块                                   | 战斗与剧情可脱离 UI 测试，随机数可重复            |
| 应用状态     | 游戏 session store 加 UI 订阅                            | 按状态片段更新界面，不逐帧重建 React 树           |
| 本地持久化   | expo-sqlite，独立快照与历史表                            | 事务提交、恢复、导入和版本迁移                    |
| 临时传输文件 | 应用私有目录与缓存目录                                   | 流式接收，校验通过后才写正式存档                  |
| 音频与触感   | Expo 对应模块                                            | BGM、音效、震动及前后台生命周期                   |
| 局域网桥接   | 本地 Expo Module，Swift 与 Kotlin                        | 服务发现、连接、配对、文件流和进度事件            |
| 内容         | 受校验的 JSON、图集、音频、字体                          | 数据驱动长篇生产，稳定 ID 支持旧档                |
| 图鉴交付     | 共用种族数据与资源索引，生成独立图鉴册                   | 游戏内展示与最终 PDF／可编辑数据保持同版本        |

SDK 57 对应 RN 0.86 系列；最终补丁版本按初始化时的兼容组合锁定。Skia 有 Android 与 iOS 支持，但本项目的地图性能仍须实测。[Expo SDK 57](https://expo.dev/changelog/sdk-57)、[Expo Skia 文档](https://docs.expo.dev/versions/latest/sdk/skia/)。

自定义原生通信模块通过 Expo Modules API 接入。完整功能使用 development build；Expo Go 不包含本项目自己的原生模块，不能用来验收传档。[Expo Modules](https://docs.expo.dev/modules/overview/)、[Development builds](https://docs.expo.dev/develop/development-builds/introduction/)。

本地数据采用 expo-sqlite，它支持应用重启后的数据库持久化。事务边界、失败恢复和导入行为由本项目实现与验证。[Expo SQLite](https://docs.expo.dev/versions/latest/sdk/sqlite/)。

## 2 模块边界

```text
app/                         页面、导航、启动与生命周期
src/game/world/              地图移动、碰撞、遭遇、NPC
src/game/battle/             行动排序、伤害、效果、结算
src/game/story/              任务、事件条件、有限指令解释器
src/game/creatures/          能力、经验、进化、技能学习与成长记录
src/game/session/            当前冒险状态、命令队列、检查点
src/rendering/               Skia 场景、镜头、图集、动画
src/features/               队伍、仓库、背包、图鉴、商店等 UI
src/persistence/             快照、校验、迁移、恢复、槽位
src/transfer/                传档状态机、配对界面、预览与导入
src/content/                 种族、技能、物品、剧情与地图索引
modules/lan-save-transfer/   Swift／Kotlin 本地 Expo Module
assets/                     像素图集、音频、字体
tools/content/              地图导出、内容引用与可达性检查
tools/encyclopedia/         正式数据导出、图鉴排版输入、完整性检查
tests/                      规则、存档、协议与内容回归
```

这是拟建目录，不是当前已有模块。规则层不导入 React、SQLite 或网络对象；保存和传输只接受明确版本的快照。UI 动画由已结算事件驱动，不负责直接扣血、发奖或修改剧情。

移动规则采用固定逻辑步进，渲染独立插值。镜头、行走帧和技能动画使用渲染侧值更新；不要把所有地块、角色位置逐帧写入 React state。只绘制可见区域及少量边界缓存，按场景加载资源并释放上一地图不用的图集。

### 2.1 精细像素资源

地图地块以 32×32、角色以约 32×48、精灵战斗帧以 128×128 为制作基线，大型精灵可使用 192×192。战斗图集记录统一锚点、包围盒、动作帧和时长；显示尺寸与素材画布独立，避免更高分辨率导致精灵占满战斗界面。

资源使用统一像素密度与最近邻采样，图集为精灵和地块保留必要的边缘填充，避免取样串色。镜头移动、图块接边、前景遮挡和像素字体分别验证；UI 文字在设备清晰度下渲染。

地图按地面、装饰、角色、前景与特效分层，角色和可遮挡物按脚底深度排序。环境光影与粒子数量设置上限，低特效模式保留关键动作。这里只定义渲染要求，具体 Skia 实现需要样板验证。

250 种精灵的素材随包提供，但不同时解码或上传到 GPU：战斗只准备当前双方及必要候补资源，图鉴列表使用小图标，详情页按需加载该物种图像。原始美术母版保留在制作资源中，运行包只含实际需要的图集与尺寸。

### 2.2 精灵与图鉴的统一数据

种族定义统一提供 `speciesId`、`dexNumber`、`familyId`、阶段、属性、六维基础能力、成长曲线、进化条件、学招表、基础捕获率、生态介绍和资源索引。栖息地与遭遇条件从地图遭遇表关联生成，避免图鉴写了一个地点而游戏里找不到。

实际 `src/content/habitats/index.ts` 定义 48 个生境并关联 115 家族和 250 形态。地图普通池、局部分区、水域调查、图鉴与地区地图从该表读取；完整导出为 `docs/data/habitat-plan.json`。自然栖地不等于当前获取：显式区分野生、进化、剧情赠予和剧情相遇，以及未开放区域。新增随机发现只取所在陆地分区的普通精灵；旧档既有发现保持不变。完成捕捉入门后，岸边面对水格可启动该水域野生战；ch3.1 获得渡水装备或剧情冲浪能力后也可进入普通水面移动。

属性使用可扩展且去重的 `types` 数组，至少含一个标准 ID，不设固定数量上限。首版使用宝可梦主系列的 18 种标准属性，包含冰；不能写死成 `primaryType/secondaryType` 或固定三项元组。三属性及以上为本作扩展，基础相克仍使用标准表。当前 250 种的分配与关系来源见[统一设计数据](data/creature-types.json)和[可读设计表](creature-types.md)。

防御倍率为技能攻击属性对目标全部属性的关系乘积，算法必须读取完整数组，不能截断、取最大值或人为限制倍率。任意一项为 0 则直接产生免疫结果，伤害路径必须在 `max(1, ...)` 等最低伤害钳制之前返回 0。本系加成通过集合成员判断，只应用一次。技能属性来自技能定义，不能直接把攻击方所有属性都乘成一次攻击。属性顺序不改变结果。

`typeChart` 显式记录 18×18 共 324 项有方向的倍率，取值仅为 0、0.5、1、2。依据[宝可梦官网属性表](https://sg.portal-pokemon.com/game/type-chart/)逐项核对，禁止从反向克制推导抵抗，也不假设同属性中性。`ruleset.source` 记录来源与核对日期，关系版本纳入 `contentVersion`；图鉴、技能提示、AI 与导出册调用同一份计算规则。此表不采用 Pokémon GO、卡牌或招式／特性／道具的特殊覆盖规则。

原 `wind` 转为 `flying`；原 `spirit` 已按种族重新分配到 `psychic` 或 `fairy`。名称使用一般、飞行、岩石、幽灵、恶等标准写法，普通、风、岩、鬼、暗仅作为本作查询别名，不能作为额外属性 ID 进入矩阵。冰属性使用独立的 `ice`，不能继续用水替代寒冰设定。

AI 对明确免疫的伤害行动评分为零，并考虑其他技能、换人或可用状态行动；PP 耗尽的无属性反伤兜底技能另走明确路径，不能错误标为一般属性后被幽灵免疫卡住，也不向物种属性表新增“无属性”。

游戏内收集状态属于存档，种族资料属于内容包，二者分离。见过、获得、已探索地区决定游戏内显示哪些资料；独立完整图鉴从正式内容包生成，不读取玩家私人存档。

250 个形态使用唯一编号，115 个家族使用稳定 ID。原 001～150 的名称、ID 与属性保留，新形态追加为 151～250，不通过重排编号覆盖旧物种。进化图需无循环且目标存在，学招表引用有效技能，所有种族都必须有可达的获取路径。换色、皮肤和动作帧不能生成新的物种编号。

最终图鉴生成流程为：冻结内容版本 → 导出种族／技能／进化／遭遇资料 → 关联正式形象 → 生成索引与条目 → 输出可检索 PDF 和可编辑 JSON → 检查排版、条目完整性与版本一致性。具体排版工具在最终制作时确定；当前不生成占位图鉴。

### 2.3 成长与进化数据

所有形态配置六项整数 `baseStats`、`baseStatTotal`、`experienceCurve`、`captureRate`、`evolvesFromId` 和显式 `evolutions` 列表。进化边指定目标与 `level` 或 `item` 条件，道具条件包含物品 ID、最低等级与成功后消耗标志。家族共用经验曲线，单体与最终阶段的进化列表为空。

`src/game/growth/index.ts` 定义 Lv.1～100、每次升级 1～10 能力点、六维分配与自动推荐。`training` 记录模式、独立种子、最多 99 次成长点数、六项已分配值和旧档固定加成。种族能力、当前能力、已投入点数与战斗临时升降分别计算；不生成新的随机个体值，不采用性格和努力值。全部 250 份方案以 `src/content/training/index.ts` 为源，导出到[培养数据](data/training-plans.json)。

经验使用累计整数，允许连续升级；Lv.100 钳制经验并停止发点。每个等级的随机结果只依赖实例种子、目标等级和固定家族强度档，不占用战斗随机流；进化不重新划档，重塑不重抽。高等级入队补齐全部历史等级点数，敌方自动分配，捕获后允许重新手动分配。旧档首次操作把已有个体能力贡献冻结，精确保留当前六维与损伤，然后补齐未分配点数。

城市委托与商店由 `src/content/cities/index.ts` 配置。`cityServices` 保存委托状态、调查印记余额与兑换次数；导入核对「已领奖总印记 − 兑换花费 = 余额」，拒绝未来未开放城市的委托或兑换记录。购买、交付、奖励和兑换只通过命令事务修改；道具与旅费容量先全部检查，不能半扣物品或重复领奖。

同一事务处理进化、对应道具消耗、图鉴、新学招队列和成长记录；取消、条件不足或写入失败不消耗道具。前置形态、目标与条件再次校验，防止旧异步回调重复进化。当前 HP 为 0 时重算后仍为 0，否则保留受到的绝对伤害并约束在新最大 HP 内。

### 2.4 通用技能学习

`src/game/skills/index.ts` 校验 `copyMove` 命令：来源和接收方必须在自有队伍或仓库，来源当前掌握有效技能，库存大于零，且没有战斗、对话或成长选择。除内部兜底与专属技能外，通用学习不限制种族、属性和等级；剧情通用招式还需先完成对应故事，复刻不能提前解锁。接收方不能重复携带同一技能；四招满位必须指定有效替换位置。所有校验先于状态修改，成功后才同步扣除技能复刻剂、更新技能与成长记录；来源不变。

接收实例 `taughtMoves?: string[]` 保存永久技能册，进化沿用实例，当前四招和技能册分别保存。城镇回忆取「当前种族已到等级学招」与技能册的去重并集，支持空槽加入或明确替换；复刻不限等级，不改变原技能类型、效果或本系判定。旧存档无字段时按空技能册处理。schema 仍为 1，内容 ch3.1 可读 ch3.0、ch2.3、ch2.2、ch2.1、ch2.0、ch1.3、ch1.2、ch1.1；导入严格拒绝未知、重复及内部技能 ID。

### 2.5 速度额度与隐藏阶段

`src/game/combat/index.ts` 共用有效速度比较、每轮 1～3 次技能额度、命中概率、要害概率、阶段限制和展示文案。技能优先度先于有效速度；并列才消耗战斗 RNG。额度在换人／用药后、技能执行前锁定，技能内速度变化从下一轮生效；先手方连续用同一招，再由另一方执行。每次独立扣 PP 和抽命中／要害，不重选 AI 意图。命中任一昏厥便停止旧行动，不跨新对手继续追击。

`Stages` 在原五项基础上追加可选 `accuracy`、`evasion`、`critical`、`criticalGuard`。前两项允许 -6～6，后两项 -3～3；schema 严格校验，旧阶段缺省为 0。新战斗与换人初始化为零；战斗快照完整保存，恢复后同一 RNG 与命令得到同样下一轮结果。多次出手在一个规则命令内原子结算，UI 逐行展示已结算战报，不持久化半次攻击。睡眠和麻痹判定用本轮临时缓存，轮末异常只结算一次。

`calculateDamage` 先算普通伤害并取整，要害再精确乘 2；属性免疫依旧提前返回 0。`criticalChance` 合成进攻阶段、招式倾向及目标抗要害，不作用于变化招、治疗或异常损伤。所有新技能走原学招／回忆／复刻通道；自然学招按等级稳定排序，新生成精灵至少保留攻击招。战斗界面状态卡显示速度及次数，战报与隐藏属性分开切换以保留实际战报的可读空间。导出见 `tools/export-combat.ts` 与 `docs/data/combat-rules.json`。

## 3 运行状态与检查点

主要模式为 `title / exploring / dialogue / battle / menu / transferring / transitioning`。输入先进入命令队列，单一 session 处理器验证当前模式后提交状态，防止两次捕捉、重复买卖或边切图边存档。

| 操作       | 内存状态变化                              | 可持久化边界                         |
| ---------- | ----------------------------------------- | ------------------------------------ |
| 移动       | 先检查目标格与事件，再完成一步            | 停在合法格后；每 10 秒周期保存       |
| 切图       | 解析入口与目标格，加载目标资源            | 目标地图可进入、位置合法后           |
| 对话       | 每个有限指令执行一个可恢复步骤            | 指令完成后；带奖励指令必须事务化     |
| 战斗回合   | 一次选择生成完整回合事件                  | 整回合规则结算完成后，播放动画前提交 |
| 捕捉／奖励 | 消耗、获得、图鉴、事件标志一并变化        | 同一份快照一次提交                   |
| 传档       | 冻结一个已提交快照，暂停目标 session 写入 | 接收校验通过后原子切换槽位           |

战斗快照保存双方精灵、回合号、阶段、已确定的 AI 意图、随机数状态与待处理的学招／进化事项。恢复时不重复播放长动画，从最近已提交的决策点继续；未提交回合整体回退。结算奖励使用稳定事件 ID，恢复时不重复发放。

学招与进化是可恢复的待选队列，不要求在一帧内完成所有 UI 选择。新快照中的奖励和待处理选择一同保存，避免拿到经验却丢失学招机会。

进化保持精灵实例 ID 不变，在同一个提交中更新种族、重算能力、更新图鉴、添加成长节点和新学招事项；取消进化只取消本次演出与选择，不清除已满足的资格。伤害与异常状态按统一规则继承，昏厥精灵不会因重算能力被意外复活。

进化同时按新种族定义替换完整属性列表，展示新增、移除或保持的属性。永久属性由种族与内容版本推导，存档不另存一份可能与种族定义矛盾的固定主副属性字段；跨设备恢复时从兼容内容包得到相同列表。

转入后台时释放按键、暂停模拟与音频，尽力提交安全快照。返回前台时重置帧时间基准，不能补跑后台数分钟的逻辑。局域网传输转后台则取消当前会话，重新进入后手动重试。

### 3.1 探索随机状态与自由道馆

探索视口铺满窗口，HUD 与半透明操作区覆盖其上，仅操作区加安全边距；地图宽高从逻辑地图读取，镜头边界与碰撞使用相同尺寸。室外增加支路、回环、分区生态和有限随机发现，不通过缩放贴图改变地图体量。

`world` 为向后兼容的可选探索状态，包含独立种子、NPC 巡走索引/朝向/步数、发现点位置/内容/领取状态与待触发相遇。旧档在安全操作中初始化；探索 RNG 与战斗 RNG 分开。接收时验证巡走定义、路径索引、发现候选格、普通种族和奖励，动态人物位置参与碰撞与存档站位校验。

道馆之间不设置徽章前置。入门后仅验证本馆练习与机关；森林和地区调查保存独立进度。未来八馆须以已获徽章 ID 集合验证联盟资格，不能只累加数字或把内容编号当作完成顺序。当前草系与岩石系两馆可任意先后，快照通过两馆独立标记核对徽章数；其他六馆尚未开放。

稀有与神兽的获取来源按家族保存在 `acquisition-plan.json`，普通遭遇和随机发现共用排除规则；剧情定点相遇单独验证前置、失败重试和已捕获标记。当前旧铃雾铃灵与矿山鸣钟石已实现，其他剧情家族随对应区域制作。

## 4 存档身份与内容

### 4.1 身份字段

| 字段               | 用途                                          |
| ------------------ | --------------------------------------------- |
| `gameId`           | 固定应用游戏标识，拒绝其他游戏的文件          |
| `schemaVersion`    | 存档结构版本，用于有序迁移                    |
| `contentVersion`   | 内容包版本，用于地图、精灵与事件兼容检查      |
| `lineageId`        | 冒险最初创建时生成，跨设备复制保留            |
| `revisionId`       | 每次提交生成的唯一版本 ID，不依赖手机时间     |
| `parentRevisionId` | 上一版本 ID，方便标识继承关系，不用于自动合并 |
| `branchId`         | 本机分支 ID；导入后第一次提交生成新的分支     |
| `localSlotId`      | 仅本机使用，不跨设备覆盖相同编号的槽位        |
| `savedAt`          | 展示时间，不能用于自动判断哪份进度应该胜出    |
| `playTimeSeconds`  | 实际前台冒险时长，不含暂停和传档              |

不依赖设备 ID、账号 ID 或登录令牌。导入保留精灵实例 ID 和冒险来源，新生成本地槽位关联与分支。相同 `revisionId` 和内容哈希重复到达时识别为重复请求，不新增奖励或多次切换槽位。

### 4.2 业务载荷

```text
player          名字、外观、金钱、当前位置、朝向、最近治疗点
progress        章节、徽章、工具能力、主线与支线阶段、通关状态
world           地图机关、NPC 事件、已拾取物、已击败训练师
creatures       实例字典、等级、累计经验、能力点、逐级成长、培养模式、旧档固定加成、当前形态、成长节点、队伍与仓库引用
cityServices    居民委托状态、调查印记余额与兑换次数
inventory       普通道具、关键道具及数量
dex             已见与已获得种族 ID；地区可见性由探索进度推导
rng             可序列化随机数状态、遭遇保护步数
battle          可选的稳定回合恢复状态
pendingChoices  学招、进化等需要玩家继续处理的事项
metadata        版本、冒险身份、保存时间和游戏时长
```

能力值由种族、等级、分配点数与旧档固定加成重新计算；经验曲线与进化条件从兼容内容包取得，导入时校验等级／累计经验一致、逐级点数与种子一致、分配不超总额、印记收支平衡、当前 HP 和技能 PP。种族能力、整套种族配置和经验表不重复复制进每只精灵的存档；载荷不包含贴图、音频、代码、绝对文件路径、数据库文件或网络会话密钥。

成长记录只保留捕获、进化和有限的重要等级／学招节点，每只最多 32 条；捕获与进化节点必须保留，其他节点按最旧优先修剪。不记录每次攻击或每一点经验变化，避免成长日志使存档无限增大。完整的当前等级、经验、形态和技能始终保留。

### 4.3 存储结构

建议表为 `save_slots`、`save_snapshots`、`protected_backups`、`import_receipts` 和 `device_settings`。快照包含结构化 JSON 文本、哈希、版本和摘要；槽位只保存当前快照指针。首版不把每个业务字段拆成单独 SQL 表，降低整段冒险导出和迁移复杂度。

每次保存先生成不可变快照并校验，再在一个独占事务中插入快照、更新指针、修剪普通历史；成功提交后才改变 UI 的“已保存”状态。写入串行化，禁止旧异步保存覆盖更新的状态。

保留每槽最近 10 个历史快照和独立的覆盖前保护备份。保护备份不随普通历史轮转删除。空间不足时保留当前可用快照并报错，不先删除当前存档腾位置。

启动检查当前快照的校验和、结构和业务约束；若损坏，列出可用历史及时间供恢复。数据库本身打不开时保留原文件，不静默清库；后续支持人工恢复或诊断导出。

## 5 本地传输格式

传输使用应用协议，不直接复制 SQLite 数据库及 WAL 文件。格式建议由有界 JSON manifest 和 UTF-8 JSON payload 构成；首版不压缩、不使用 ZIP，减少跨平台差异和解压体积问题。

| 内容          | 字段或限制                                                               |
| ------------- | ------------------------------------------------------------------------ |
| 协议头        | 固定 magic、`protocolVersion`、`transferId`                              |
| manifest      | `gameId`、schema／content 版本、revision／lineage、字节数、SHA-256、摘要 |
| 载荷          | 业务快照的 UTF-8 原始字节                                                |
| manifest 限制 | 不超过 16 KiB，字符串长度和字段数量受限                                  |
| 载荷限制      | 不超过 8 MiB；目标正常存档小于 2 MiB                                     |
| 分块          | 64 KiB，包含序号和实际长度，最终总长度必须一致                           |
| 哈希          | SHA-256 覆盖 payload 的确切字节，manifest 另由认证会话保护               |

发送前一次序列化，摘要与载荷来自同一个冻结快照。接收端先校验字节和哈希，再解析 JSON、迁移、校验业务状态，并从实际载荷重新生成摘要，与用户确认的摘要核对。

JSON 校验采用白名单对象重建，拒绝未知版本、非法数值、重复实例、悬空引用、超大数组和异常嵌套；不把外部对象直接深合并进当前状态。地图与坐标必须合法，道具与精灵 ID 必须存在，关键进度要符合内容包约束。

哈希证明传输完整性，不证明存档来自不可修改的官方游戏。首版是离线单机，不建立反作弊服务器或跨玩家经济体系。

## 6 发现、连接与配对

### 6.1 服务发现

接收端进入等待页后发布 DNS-SD 服务，暂定类型 `_stargrovesave._tcp`，实现前检查服务命名约束并固定。发布内容只含临时会话 ID、设备别名、协议版本与可用状态，不广播玩家名字、徽章和完整存档。

Android 使用 `NsdManager`，iOS 使用 Bonjour／Network.framework 的浏览与监听能力。Android NSD 使用 DNS-SD，可与其他平台的同类服务发现互通；这只说明协议基础可行，产品仍需要实机实现与联调。[Android NSD 文档](https://developer.android.com/develop/connectivity/wifi/use-nsd)。

端口由系统分配后发布，不固定占用某个端口。设备以临时会话 ID 去重，名称重复时附加短标识；地址变化、服务移除与网络切换会清理旧条目。兼容 IPv4／IPv6，避免把地址固定为 `192.168.*`。

默认搜索 20 秒，无结果显示原因和重试入口；服务解析或连接超时 10 秒。手动地址仅绕过发现，不绕过配对、接收确认与校验。访客 Wi-Fi、AP 隔离或多播屏蔽作为明确错误路径处理。

### 6.2 配对与通信

产品流程采用两端核对短校验码并确认，再在加密连接上交换 manifest 和载荷。发现记录不作为可信身份，任何传输都要在接收端看到预览并确认。

实现约束是使用成熟的认证握手和加密实现，短码必须绑定本次握手，不能仅比较设备名或通过明文 HTTP 发送一个口令。不得把六位数字直接用作加密密钥，也不得把“信任全部自签名证书”当作认证完成。

**尚未冻结的技术决策：具体跨平台认证配对库。** M0 必须验证 Swift／Kotlin 接入、短码绑定、证书或公钥验证、重放拒绝和会话取消；再冻结详细握手字段与测试向量。若成熟实现不能满足要求，可采用扫描接收端二维码固定临时公钥和高熵会话凭据的方案，但需同步更新产品流程，不自行设计密码协议。此项是进入正式传档开发前的技术门槛。

会话只接受一台已配对发送端，一次成功导入后失效；配对等待 2 分钟超时。连续 5 次无效配对终止当前会话。用户退出、拒绝或应用进入后台时停止发现、监听、连接与临时凭据。

## 7 传输状态机与提交

```text
接收端：等待发现 → 配对确认 → 预览摘要 → 选槽并确认
        → 接收临时载荷 → 完整性和业务校验 → 本地事务提交
        → 显示完成 → 可从该存档继续

发送端：选存档并冻结 → 搜索设备 → 配对确认 → 发摘要
        → 等接收同意 → 发载荷 → 等提交回执 → 显示已送达
```

发送端不允许在存档尚未成功提交时发送。活跃冒险暂停到安全状态，战斗、剧情演出、学招或进化选择期间提示先完成当前操作。传输使用冻结快照，过程中的设置调整不会改变载荷。

接收端选槽后记录槽位当前 revision，在提交前再次比较；如果已变动，必须重新预览确认。整个接收过程暂停该槽位的自动保存和编辑，等待已有写入队列清空；导入后切换 session generation，使旧异步回调失效，防止老内存状态覆盖新档。

提交在单个事务中完成：保留覆盖前备份、插入验证后的快照、切换槽位指针、写入 `import_receipts`。任意一步失败都回滚，现有指针保持原值。真正提交后重新读取并重建 session，之后才显示成功。

协议消息至少包括 `HELLO`、`OFFER`、`ACCEPT`、`REJECT`、`DATA`、`FINISH`、`COMMITTED`、`QUERY_STATUS` 和 `CANCEL`。每条消息携带会话和传输标识，设置最大长度。数据流留在原生模块中，JS 只收进度与结果，不把每个二进制块转成 Base64 跨桥传递。

### 7.1 断线和回执

传输进度以实际写入字节计算。连续 15 秒无数据则超时，整次传输上限 120 秒。传到 100% 后另显示“正在校验”“正在保存”，不能提前显示完成。

首版不做分块断点续传：提交前断线就删除临时文件，重新确认后重传，8 MiB 上限下保持流程简单。提交完成但回执丢失是另一种情况：发送端显示“尚未确认接收结果”，再次配对后用 `transferId` 与 payload 哈希查询已持久化回执，避免重复导入。

提交回执保留最近 100 条。被查回执已清理时，接收端再根据当前槽位的 revision 和哈希判断是否已经收到；无法确认则保留不确定提示，让用户检查接收端，不声称传输失败或成功。

### 7.2 异常结果

| 情况             | 用户看到的结果                         | 数据处理                                   |
| ---------------- | -------------------------------------- | ------------------------------------------ |
| 没有本地网络权限 | 说明用途，提供设置与重试               | 不开始监听或连接                           |
| 搜不到设备       | 检查接收页、同网、访客隔离；可手输地址 | 原存档不变                                 |
| 设备离开或切网   | 连接已中断，可重新搜索                 | 停止旧会话，清理未提交临时数据             |
| 配对不一致或拒绝 | 已取消配对                             | 不发送存档详情和载荷                       |
| 协议或内容不兼容 | 显示需要的游戏版本                     | 不接受导入                                 |
| 数据损坏／超限   | 存档校验失败，列出可理解原因           | 不更新目标槽                               |
| 空间不足         | 无法保存，保留原进度                   | 回滚事务，不删除唯一可用版本               |
| 用户取消         | 显示已取消或已提交完成                 | 提交前取消回滚；提交后保留成功结果         |
| 提交后失去回执   | 发送端显示结果待确认                   | 接收端保持已导入状态，支持状态查询         |
| 接收进程被终止   | 下次启动检查事务和回执                 | 要么保持旧档，要么完整新档，不存在半份存档 |

## 8 跨版本与分支

应用版本、存档 schema 版本和内容版本独立。新版本只接收明示支持的 schema／content 范围；schema 使用连续的纯函数迁移，先在内存中迁移副本并完整验证，再写入新快照，旧版本备份保留。

旧应用遇到更高版本存档时拒绝并提示升级。相同 schema 也不代表内容兼容：如果新地图、种族或事件 ID 在接收端不存在，同样拒绝，不能偷偷丢掉未知精灵或任务。

内容改名不改 ID。地图移除或入口调整必须提供坐标迁移；只有明确迁移规则允许时才回到安全治疗点，不能用默认位置掩盖损坏存档。

跨设备的同一 lineage 可以有多条分支。预览显示“同一冒险的另一份进度”、徽章、位置和时长，由用户选整份导入；不自动选时间较新、徽章更多或金钱较多的一份。

当前 `ch2.1` 明确兼容读取 `ch2.0` / `ch1.3` / `ch1.2` / `ch1.1`，旧冒险不回放新增序章。仅新冒险救博士之前允许空队伍；伙伴借用、正式赠送、对手胜利、图鉴补给各有独立事件标记，分别校验前置并保存。新内容快照不能回传给仅支持旧内容的客户端。八馆的计划依赖另见 [campaign-plan.json](data/campaign-plan.json)，不会把尚未实现的后续地图或徽章伪装成当前存档支持内容。

## 9 平台与构建

### 9.1 Android

配置源通过 `expo-build-properties` 设置 `buildArchs: ["arm64-v8a"]`。生成的 Gradle 配置应具有同一架构限制；正式 APK／AAB 再检查所有原生库目录，不能只看配置文件。[Expo BuildProperties](https://docs.expo.dev/versions/latest/sdk/build-properties/)。

正式构建启用 R8 和资源裁剪，像素资源以图集合并并检查无损显示效果；压缩措施逐项验证启动、通信和动画，不以静态包体变小替代运行验证。调试与正式包均以 ARM64 真机或 ARM64 模拟器为基础。

网络权限按实际系统和 target SDK 分支实现。Android 官方文档当前规定：target SDK 37 及以上采用 `ACCESS_LOCAL_NETWORK` 运行时权限或相应系统设备选择方案；target SDK 36 及以下不要提前声明或请求该新权限。自定义双向接收与设备列表在 M0 验证适用路径，并覆盖拒绝和设置中撤销后的行为。[Android 本地网络权限](https://developer.android.com/privacy-and-security/local-network-permission)。

不为了局域网发现索取通讯录、相册或精确定位。权限应只在进入传档功能时按具体 API 要求申请。首次发布 target SDK 和最低 Android 版本在依赖矩阵与发布要求确认后锁定。

### 9.2 iPhone

使用原生 Network.framework／Bonjour 的实现，并在 Info.plist 配置 `NSLocalNetworkUsageDescription` 与具体 `NSBonjourServices`。首次进入传档时解释本地网络用途；拒绝后保留离线游戏并提供前往设置的路径。[Apple 本地网络隐私说明](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)。

先使用声明了具体服务类型的系统 Bonjour API，不默认增加任意原始多播能力；如选中的实现需要额外 entitlement，在 M0 核对 Apple 要求并记录原因。局域网监听仅在传档界面前台运行。

iPhone 正式支持不等同于模拟器能启动。开发和发布包均需具备正确签名、安装与真机权限验证；最低 iOS 版本在原生依赖兼容性确认后锁定。

## 10 性能与包体目标

下列是验收目标，未进行实测。M0 选定一台中端 Android ARM64 手机和一台较旧但受支持的 iPhone 作为基准，并记录机型、系统、构建类型和测量条件。

| 项目               | 初始目标                                                |
| ------------------ | ------------------------------------------------------- |
| 地图与普通战斗动画 | 60 FPS；不适合的设备提供 30 FPS 模式                    |
| 输入到移动反馈     | 常规探索目标不超过 100 ms                               |
| 冷启动到标题       | 基准真机目标 3 秒内                                     |
| 继续到地图可操作   | 基准真机目标 2 秒内                                     |
| 普通地图切换       | 目标 500 ms 内；大资源切换显示过渡                      |
| 存档载荷           | 通常小于 2 MiB，拒绝超过 8 MiB 的传输载荷               |
| 存档互传           | 同网正常条件下，用户确认后的 2 MiB 载荷目标 10 秒内提交 |

| Android APK        | ARM64 release 暂按 250 MiB 内规划，完成素材样板后重估   |

渲染降级只调整特效数量、动画帧率和预加载范围，不改变战斗数值或剧情。连续探索与战斗 30 分钟后检查温度、掉帧和资源释放。

250 种精灵需要至少 500 组正背面动作素材与 250 个小图标，包体目标在采样后重新校准；只加载当前场景与详情资源，避免随图鉴总数线性增加常驻内存。用完整精灵动作、城镇／森林地图和长列表记录解码内存及包体贡献，不能只按 PNG 文件大小推算。若超出预算，优先优化图集、重复帧、加载与缓存，内容目标的调整需更新明确决策。

## 11 验证矩阵

### 11.1 规则与内容自动验证

- 相同种子和指令产生相同战斗结果；先制、速度并列、多属性、状态、昏厥与换人符合规则。
- 捕捉成功、失败、满仓、重复命令、用药与 PP 耗尽，不重复消耗或生成实例。
- 奖励、学招、进化与主线开路在恢复检查点后只结算一次。
- 每个地图入口目标存在且可站立，关键路线可达，任务不会引用不存在的物品／事件。
- 不同伙伴开局都能完成首章；图鉴全部种族存在单机获取途径。
- 按 250 形态／115 家族目标检查唯一编号、资源、学招、进化和遭遇引用；原 150 个 ID 稳定、新增 100 种有原创概念，进化图无循环。
- 135 条进化边、12 类道具引用、全部六维总和和四条经验曲线校验通过；验证 Lv.1／100、连续升级、取消重试和满级道具进化。
- 属性表的 324 项与已核对的官方矩阵一致，250 种均使用标准属性，18 类均有物种。
- 覆盖冰的四类克制与四类弱点、一般／幽灵互免、地面免电、飞行免地面、妖精免龙、钢免毒、恶免超能力；正向、反向和免疫均独立读取。
- 三属性及更多的顺序无关乘积、本系一次加成、零倍率优先、16 倍克制与 1/16 倍抵抗均验证；进化、存档与图鉴不截断，也不固定二项或三项上限。
- 捕获→升级→学招→取消与再次进化→保存→跨平台恢复后，实例身份、形态、成长节点和图鉴记录一致。
- 游戏内图鉴与独立册由相同内容版本生成，逐项核对数量、形象、属性、进化条件、技能与捕捉地点；独立册中文可检索，索引和图片清楚。
- 精细地图接边、角色遮挡、像素缩放、精灵动作与图鉴滚动在两个平台检查，图鉴切换物种后释放不需要的大图。

### 11.2 存档故障验证

- 连续快速保存与切后台不会让旧快照覆盖新快照。
- 在快照插入、指针更新、回执写入前后强制结束进程，启动后只出现完整旧档或完整新档。
- 损坏哈希、非法 JSON、未知 ID、错误坐标、重复精灵 ID、溢出数值与超限载荷被拒绝。
- schema 迁移成功可继续；迁移失败保留旧档；保护备份不受普通历史清理影响。
- 设备时间不同不触发自动覆盖；同一 lineage 的不同分支可供用户明确选择。

### 11.3 双机真机矩阵

| 发送 → 接收       | 必须通过                               |
| ----------------- | -------------------------------------- |
| Android → Android | 发现、配对、预览、导入、冷启动继续     |
| Android → iPhone  | 同上，包含 Android 发送到 iOS 原生接收 |
| iPhone → Android  | 同上，包含 iOS 发送到 Android 原生接收 |
| iPhone → iPhone   | 同上，不用单平台专用协议代替公共协议   |

每种组合还需覆盖首次授权、拒绝／撤销权限、发现超时、重复设备名、配对拒绝、传输中切网、切后台、目标槽覆盖、损坏载荷、版本不兼容和回执丢失。测试网络包括可互通但无外网的普通 Wi-Fi，以及应正确报错的访客隔离网络。

最终证明要从 A 的指定任务与精灵状态保存，传到 B，完全结束 B 应用后重新启动，再核对地图、任务、精灵、背包与徽章并继续下一步剧情。只显示“连接成功”或传输进度 100% 不算通过。

### 11.4 发布检查

记录应用版本、构建号、Git 来源、构建环境、安装包路径与 SHA-256。检查 Android 原生库仅含 `arm64-v8a`，在正式配置运行资源和原生通信；验证 iPhone 签名与安装，以及应用升级后存档保留。最终图鉴册和数据单独记录内容版本与文件校验值，核对与安装包内内容一致。上传、商店审核、正式发布作为单独状态记录。

## ch10.3 技能归属、演出与美术

技能演出由 `src/game/battleVisuals/index.ts` 定义，战斗记录有界 `visualEvents`，携带日志位置与前后画面，不改变随机状态或重复结算。`BattleStage` 用RN Animated与SVG播放，`BattleScreen`按实际出手逐条推进；读档不重播事件。专属招式使用 `exclusiveSpeciesId`，归属在自然学招、回忆、复制、待学、使用和存档恢复中一致校验，进化交换专属且不补满PP；其附带自身强化的攻击仍按基础命中率判定。

地区战场在 `src/content/battleScenes/index.ts` 显式覆盖全部地图，精灵轮廓取图区在 `data/sprite-frames.json`，布局按最大边等比缩放并留7%边距。触感通过独立本机设置、80ms节流与平台驱动实现，失败不会影响按钮动作。实现记录和完整技能／专属清单见[实现记录](implementation.md)、[技能设计](battle-skills.md)。
