## ch10.2：强度成长、升级学招与药剂重塑

成长点仍为每级1–10点、100级封顶，取消低强度补偿，按家族最终种族总和划档：≤500为普通档，501–550为均衡档，>550为高强度档，每级期望分别为4／5.5／7点。更高强度档更偏向高点数；同一随机分位下不会少于低档。进化沿用家族档位，独立实例种子和逐级记录避免读档、暂缓进化或药剂重塑重抽。

每次升级检查当前精灵的自然学招表：技能空位直接学会，已有四招则排入选择替换队列，可暂时放弃后到精灵中心回忆。成长果与战斗升级都结算能力点，并明确显示学会的招式或待选择状态；实际选择替换后更新学习成功提示，非法替换序号不会清掉待学队列。培养页显示下一次自然学招等级与技能。

伙伴培养页移除重置入口，只可分配剩余点数；减号和「撤销未确认预览」仅修改本次尚未提交的草稿。已确认点数不会因模式切换、推荐方案或进化而转移。原`respec`道具保留存档ID并更名为「重塑药剂」，只在背包中使用：需城镇、满体力、无异常且已有加点，实际消耗一瓶后返还全部已用点数并切回手动，原等级、经验、成长记录和旧能力加成保留。

内容版本升为`ch10.2`，兼容之前受支持版本。新增可选的`training.strengthFromLevel`记录新概率开始的等级，旧记录前缀继续用原补偿规则校验，已有点数、分配与能力不重算，之后升级才使用新强度概率；新伙伴从Lv.2使用新规则。此边界随保存和传档保留，旧客户端会提示更新。250份培养方案、图鉴、代码参照与导出数据已同步。

198项测试（23个文件）、TypeScript、ESLint与格式检查通过，覆盖全部250种精灵的自然学招触发、满四招替换、升级点数、强度概率顺序、无药不能重分配、旧补偿记录混合新规则与冷读取。额外读取现有第2／3章、主线结束和通关后四份历史文件，能力和已有分配精确保留，迁移后的新快照也能冷读。

网页以正常开场的51条指令生成独立验收档，实际将重塑药剂99→98并返还21点，Lv.5→6获得8点、Lv.6→7获得10点并学会炽尾扫击；确认速度5点后剩余34点，撤销预览按钮不可退回已用点数，冷刷新保持一致。继续至Lv.9触发凝神替换弹窗，替换撞击后四招上限与点数不变，显示学习成功。截图`exports/growth-training-locked.png`、`growth-level-learning.png`、`growth-move-replacement.png`；历史保留核对见`growth-legacy-proof.json`。网页导入控件附着到文档并在完成／取消后清理，避免选择文件期间节点被回收。本次不重新打包，原生安装包仍属于下文ch10.0构建。

## ch10.1 补充：独立多存档、自由读取与分享恢复

存档不再限制为三个固定槽。原1–3槽原样保留，仓库按已占用的正整数槽号列出记录并提供下一个空槽。新冒险、Wi-Fi传档和本地管理共用槽位列表；标题页新增直接管理／导入入口，较多记录可滚动选择。「另存为新档并继续」创建带新分支的独立检查点，并把后续自动保存切到新槽，原槽不会被新分支游玩覆盖。

保存、读取、另存和退出由共用会话队列排序。修正旧界面在读取前无条件保存的问题：重读当前槽直接恢复磁盘版本，切换其他玩家则先保存离开的进度；正在进行的写入先完成，切换期间不接收额外游戏指令，延迟的自动保存不能串到另一槽。保存失败、空槽或坏档不替换正在玩的角色。Web多标签写入使用浏览器Web Locks协调，预期revision仍在锁内比较；原生继续使用SQLite独占事务。

单档、历史和保护备份均可生成`.stargrove`分享文件；「分享全部存档」把各独立槽的最新快照打成同一文件。合集带独立格式版本、整体校验与各档原有校验；单档上限8 MiB、合集上限64 MiB。新接收端可以全部新增恢复，自动分配本机空槽，不覆盖自己的记录；任何一档损坏、版本不兼容或最终写盘失败时，整个批次不落盘。单档仍可显式覆盖所选槽，二次确认并保留保护备份。合集不包含轮转历史，历史可以单独分享与恢复。

文件内容保留角色名字、伙伴、图鉴、任务、培养、道具、天气、随机状态、战斗和成长队列；没有账号、设备或发送方槽位绑定。接收者继续时创建自己的分支，发送方档案不被修改。Android／iPhone调用系统分享；分享弹窗返回后不立即删除缓存文件，避免接收应用稍后读取URI时拿不到内容。网页下载相同文件，并从系统文件选择器导入。无需在线存档服务。

本次194项测试（23个文件）、TypeScript、ESLint、格式与差异检查通过。新增测试覆盖超过三槽、跨玩家合集与单档的冷读和继续、旧版本分享、历史版本恢复、批量校验／写盘回滚、并发新增槽分配、重读当前档不覆盖、另存后的原分支保护、延迟自动保存以及失败时保留当前玩家。

网页用`127.0.0.1:8088`与独立`127.0.0.1:8092`存档库实际操作：另存至第4槽，下载合集后在已有「接收玩家」的第二个库中导入；再导出逐项对照，四份原始快照完全一致，本机原档仍在，共5档。冷刷新显示全部记录；标题页单档导入新增第6档并恢复降雨探索，任意切回第1档仍恢复接收玩家原来的开场对话。截图`exports/save-sharing-source.png`、`save-sharing-received.png`；导出对照记录`save-sharing-ui-proof.json`。没有操作原`localhost:8088`玩家存档。本次未重新打包，Android／iPhone系统分享面板与双真机恢复尚未实测。

## ch10.1：城市地面、区域气候与统一金手指

内置 image_gen 新增一张 4×4 城市地面图集，原图直接复制到 `assets/maps/city-ground-tiles.png`，完整提示与来源见美术清单。十城／联盟各用不同街道材质，后六格补充林地、海沙、工业砾石、高山草甸和火山砾土。后续城市直接按碰撞网格取材质，前四城保留原场景画，仅覆盖实际道路；大场景与小地图使用同一图层，不改变地图尺寸、碰撞、出入口或旧存档坐标。旧场景地面补层记忆化，行走时不反复重建。

战斗外天气已真实接入：每秒推进户外自由探索的剩余时间，3–6分钟轮换，菜单、室内、对话、战斗、待处理成长时暂停。现补齐全部后续区域的八类气候权重，海湾沿用海滨、雪线偏向高山雪、湖畔偏雾，炉心与海滨不自然降雪。跨区时不重置计时，不符合当地气候的旧天气在当地显示晴朗。粒子动画、HUD、步速、普通陆地／水面遭遇权重与保存状态共用天气规则；战斗入场冻结当时天气。

「菜单 → 设置 → 金手指」仅显示输入框与确认按钮，提交后给结果提示，不在界面公开指令列表。指令统一改为稳定的三位纯数字：1开头为精灵球、2为回复、3为培养、4为进化、5为重要物品；例如 `105` 领取10枚大师球、`301` 领取99颗成长果、`503` 领取渡水装备。输入框调用数字键盘并限制三位，旧字母代码失效，已有道具和存档不受影响。运行白名单生成 [完整指令表](cheat-codes.md)，无脚本执行或任意存档字段修改。普通道具可重复领取，关键工具每件一份；无效、忙碌、容量不足均不发放。背包分五类口袋，关键物品不显示消耗按钮，球在战斗中使用，进化品在伙伴页使用；正常剧情赚取的工具也显示在重要物品袋中。

## 速度与隐藏属性（ch2.3）

默认有效速度决定先后，先制招式优先。速度达到对手 2 倍有 2 次技能出手，3 倍及以上有 3 次，当前上限 3。双方在技能开始前固定本轮额度，先手方连续执行本轮选择的技能，每次独立消耗 PP、判命中与要害。PP 不足不改招，任一原出战者倒下立即取消旧行动，不追击后补目标。主动换人、用药、投球和逃跑不重复；未结束时，对手按速度额度回应。睡眠倒计时与麻痹失去行动每轮一次，毒／灼伤每轮一次。

命中、闪避、要害、抗要害为临时战斗阶段；不改变原有 1～10 点／100 级的六维培养。基础要害率 6.25%，1／2／3 级分别 12.5%／25%／50%；招式可自带要害倾向，抗要害每级减半。要害按普通伤害取整后精确 ×2，免疫仍为零，治疗／异常扣血不翻倍。新增凝神、鹰眼、轻身、影步、守心、破绽突刺六招，接入自然学习、旧伙伴免费回忆和通用复刻。250 份培养建议与 `docs/data/combat-rules.json` 同步导出。

状态卡显示双方有效速度和每轮次数；技能页提示逐次扣 PP。战报默认先显示实际行动，按钮切换隐藏阶段、当前命中与要害率；结束结果与战报不同时覆盖。伙伴详情可展开隐藏属性规则。新增阶段以兼容可选字段保存，读取旧 ch2.2 等战斗缺省为零；新客户端内容为 ch2.3，schema 仍为 1。

## 存档与协议

`save_slots`、`save_history`、`protected_backups`、`import_receipts` 保存有界 JSON。写入串行化，预期 revision 比较防止旧异步覆盖；SQLite 独占事务成功后才显示保存成功。快照包含 lineage / branch / revision / parent revision、版本和确切 payload 的 SHA-256。

业务载荷保留完整战斗决策点、AI 意图、随机数和学招 / 进化队列；恢复不会重新发奖。当前接受 schema `1`、内容 `ch3.1`、`ch3.0`、`ch2.3`、`ch2.2`、`ch2.1`、`ch2.0`、`ch1.3`、`ch1.2` 与旧 `ch1.1`。旧档没有新序章标记，按原有进度继续；首次新提交保留 lineage 和父 revision 并升级内容版本，不收走伙伴、不回放序章。Zod 与业务检查拒绝未知版本、哈希不符、非法坐标、未知内容 ID、悬空引用、重复实例、异常 HP / 等级和过大载荷。18×18 共用表按完整属性数组叠乘，免疫优先，本系只加成一次。

新序章救援前允许合法空队伍快照，其他游戏阶段仍拒绝空队伍。检查新序章事件前置，未获得伙伴时禁止野外随机战；未领取捕捉补给前不开放捕捉教学。选择博士背包、对话、战斗和待处理成长期间禁止传档，稳定的空队伍检查点可正常传输。

发现服务 `_stargrovesave._tcp` 使用动态端口；广播只含协议版本、会话 ID 和别名。发送方选设备后扫描配对码，也可直接扫描 / 粘贴完整码连接。二维码固定临时 Curve25519 公钥和 256 bit 会话凭据，2 分钟失效。搜索 20 秒、连接 10 秒超时。进入后台取消，瞬时 inactive 权限提示不取消。

预览、确认、数据和回执通过 TweetNaCl box（Curve25519 / XSalsa20-Poly1305）加密；双向独立 nonce 计数，校验会话并拒绝反射 / 重放。单块 64 KiB、逐块 ACK、整体上限 8 MiB、帧缓冲有界。块经原生 TCP 库 JS API 传递，**尚非早期草案的原生文件流**；极限文件内存需设备实测。

接收端先预览选槽，长度 / SHA / 版本 / 业务校验成功后，在同一事务写存档、保护备份与回执。提交前失败保留旧档；提交中取消等待事务结果；提交后 ACK 丢失可重连 QUERY_STATUS 查询，避免重复导入。不按设备时间或徽章数自动选档、不合并分支。

## 构建与复现

Node 22 / pnpm 10；Android SDK 36 / JDK 21 或 Xcode / CocoaPods。执行 `pnpm install --frozen-lockfile` 后生成对应工程。不要在原生构建运行期间 prebuild。

```sh
pnpm exec expo prebuild --platform android --no-install
cd android
./gradlew :app:assembleRelease
```

配置有效 `ANDROID_HOME` / `JAVA_HOME`。APK 在 `android/app/build/outputs/apk/release/app-release.apk`。正式入口是 `index.ts`，不传审计 init script；检查实际 APK 原生库仅 `arm64-v8a`。

```sh
pnpm exec expo prebuild --platform ios --no-install
cd ios
pod install
ENTRY_FILE=../index.ts NODE_ENV=production xcodebuild \
  -workspace app.xcworkspace -scheme app -configuration Release \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath ../exports/ios-build CODE_SIGNING_ALLOWED=NO build
```

审计构建在 Android 加 `-I ../tools/native-audit.init.gradle`，iOS 改为 `ENTRY_FILE=../tools/native-audit-entry/index.tsx`。安装启动后写 Documents 的 `native-audit.json` 和日志 `STARGROVE_NATIVE_AUDIT`。审计完成须恢复正式入口重新构建安装，不能交付审计包。

实测 Xcode 27 的模拟器窗口由 Device Hub 提供。模拟器包不能改成 IPA 冒充真机包。历史安装包的内容版本、大小、校验值、签名用途与源码摘要见 `exports/artifacts.json`，构建日志和截图保存在同目录；源码提交以 Git 历史为准，安装包只对应元数据记载的构建版本。
